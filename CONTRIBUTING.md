## 📋 Repository Standards

### Formatting Conventions

- **File Names:** Use hyphens for multi-word names (e.g., `incident-report.md`)
- **Directories:** Use consistent naming conventions across the repository
- **Markdown:** Follow standard Markdown formatting
- **Code:** Include clear comments and documentation

### Documentation Quality

- Clear, descriptive titles and sections
- Comprehensive README files in each directory
- Detailed explanations and context
- Proper citations for external resources
- Step-by-step procedures for technical content

### Security Considerations

- No sensitive data (API keys, credentials, PII) in commits
- No malware samples in the repository (documentation only)
- Responsible disclosure for vulnerability information
- Proper anonymization of examples and case studies

## 📚 Adding New Content

When adding new material:

1. **Create appropriate directory** - Use existing structure or discuss new categories
2. **Write comprehensive README** - Document what's in the directory
3. **Follow naming conventions** - Consistent with existing files
4. **Include proper headers** - Title, date, and context information
5. **Add to main README** - Update repository overview if needed

## 🐛 Reporting Issues

Found an error or broken link?

- Check if the issue is documented in an open issue
- Open a new issue with:
  - Clear description of the problem
  - Location (file/section/link)
  - Suggested fix if applicable
  - Environment details if relevant
